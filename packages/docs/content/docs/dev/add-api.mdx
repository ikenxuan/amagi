# 新增接口

v7 起，给平台加一个数据接口只剩一个**实质步骤**：在 `endpoints/` 下新建一份端点声明（`defineEndpoint`）。参数类型、运行时校验、请求构造、签名、HTTP 路由、fetcher 方法、返回类型全部由声明派生 —— 不再有 v6 那种「改 8 步、动 11–15 个文件」的流程。

实现之前建议先读两处真实代码找手感：

- 端点声明模板：`packages/core/src/platforms/douyin/endpoints/videoWork.ts`
- 注册表汇总：`packages/core/src/platforms/douyin/endpoints/index.ts`

## 第 1 步：新建端点声明文件

在 `packages/core/src/platforms/<平台>/endpoints/` 下新建 `<短名>.ts`，用 `defineEndpoint` 声明端点。抖音 `videoWork` 的真实声明长这样：

```ts
// packages/core/src/platforms/douyin/endpoints/videoWork.ts
import zod from 'zod'

import { defineEndpoint, type } from '../../../contracts/endpoint'
import { douyinApiUrls } from '../api'

/**
 * 视频作品详情（新路径 `/fetch_video_work`，修 #47/#48/#54 的路由冲突）。
 * 行为与 v6 的 `videoWork` 一致：`getWorkDetail` GET + a_bogus 签名。
 */
export const videoWork = defineEndpoint({
  name: 'douyin.videoWork',        // ① 端点全名：<平台>.<短名>，全仓唯一
  route: '/fetch_video_work',      // ② HTTP 路由：同平台内唯一，重复会抛错
  params: zod.object({             // ③ 参数 schema：参数类型与运行时校验都从它来
    aweme_id: zod.string().min(1, { error: '作品ID不能为空' })
  }),
  build: (p) => ({ method: 'GET', url: douyinApiUrls.getWorkDetail(p) }), // ④ 构造请求
  sign: 'a-bogus',                 // ⑤ 签名：平台签名器表里的名字
  response: type<WorkDetailData>() // ⑥ 响应类型令牌（运行时是空对象）
})

/** 作品详情响应（与 v6 形状一致的最小声明） */
export interface WorkDetailData {
  aweme_detail?: {
    aweme_id?: string
    desc?: string
    [key: string]: unknown
  }
  [key: string]: unknown // 顶层索引签名：平台以后加字段不算 breaking
}
```

换成你的接口时，逐个替换这些字段：

| 声明字段 | 做什么 | 取值来源 |
| -------- | ------ | -------- |
| `name`   | 端点全名 `<平台>.<短名>` | 该平台已有声明的命名习惯 |
| `route`  | HTTP 路由路径，**同平台内唯一** | v6 的路径风格（snake_case）保持不变 |
| `params` | zod schema | 参数类型和校验的**唯一出处**，不再手写第二遍 |
| `build`  | 按参数构造请求描述 | URL 构造放在同目录 `api.ts` 的纯函数里 |
| `sign`   | 签名声明 | 平台签名器表里的名字；不签名的接口写 `false` |
| `response` | 响应类型令牌 `type<Foo>()` | 响应类型与 v6 实测形状一致，带顶层索引签名 |

字段全貌与 `prepare` / `decode` / `paginate` / `judge` / `normalize` / `compute` / `retryOn` 等可选槽位见[项目架构](/docs/dev/architecture)的「端点声明」一节 —— 每种可选槽位对应一种非常规端点形态，需要时在**这一个文件里**写，不用新增其它文件。

## 第 2 步：登记进 registry

在平台注册表汇总文件（`endpoints/index.ts`）里把新声明登记进去：

```ts
// packages/core/src/platforms/douyin/endpoints/index.ts
import { videoWork } from './videoWork' // import 新声明

export const douyinRegistry = {
  // …… 现有端点
  videoWork, // 登记进 registry
} as const satisfies Registry
```

登记后顺手做两件机械事：把声明与响应类型加进该文件尾部的 re-export 列表（照抄现有行），并同步平台端点测试里锁定的注册表数量判据（douyin 现有 19 个，加一个就是 20）。

## 这一步之后：全部自动派生

登记完成即接口可用，以下东西**不需要你维护**：

- **fetcher 方法。** `client.douyin.fetcher.fetchXxx` 与静态 `douyinFetcher.fetchXxx` 都从 registry 派生（Proxy 懒加载，方法集合自动跟随注册表），参数与返回类型由声明推导，自动走 v7 信封。
- **方法名。** 默认按「`fetch` + 短名首字母大写」规则派生；只有不规则名（如 `search` → `searchContent`、`parseWork` 无 `fetch` 前缀）才需要去 `client/method-names.ts` 加一行 —— 那是全仓唯一手写映射表。
- **校验。** 参数 schema 即校验，校验失败返回 `success: false` 信封（不再 `throw`）。
- **HTTP 路由。** `route` 由服务端自动注册成 `/api/<平台>/<route>`，不再手写路由文件。
- **返回类型。** `response` / `normalize` / `compute` 推导出精确类型；声明过的字段有补全，平台新加的字段读出来是 `unknown` 而非编译错误。
- **文档与测试清单。** 方法与路由清单由注册表推出，不再有手写的 `api-spec.ts` 之类的第二份事实。

### 常见形态的写法

| 你想做的事 | 写法 |
| ---------- | ---- |
| 无参接口 | `params: zod.object({})`，fetcher 方法可以省略 options（见抖音 `emojiList`） |
| 数字参数（可传字符串） | `zod.coerce.number()`（快手的 `count` 就是这么强转的） |
| 必填与文案 | `zod.string().min(1, { error: '中文提示' })`，文案直接写在 schema 上 |
| 声明式翻页 | `paginate` 槽位声明 `maxPageSize` / `items` / `hasMore` / `nextParams`（见 `userFavoriteList`） |
| 不签名的接口 | `sign: false`（见抖音 `search` / `emojiList`） |

## 验证

```bash
pnpm typecheck  # 类型检查
pnpm lint       # 代码检查
pnpm test       # vitest：端点级用例 + fetcher 表面快照 + registry 结构锁
pnpm deps:check # dpdm：必须报 0 环（依赖方向没破才会过）
```

用你的新接口跑一次端到端：`client.<platform>.fetcher.fetchXxx(...)` 成功返回信封后，任务就完成了。

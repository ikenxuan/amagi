# 公开 API 表面

## 默认导入是什么

默认导出 `amagi` 是可调用也可 `new` 的工厂，与 `amagi`、`CreateApp` 同源。具名 `createClient` 返回同一个新门面，类型为公开的 `AmagiClient`。

```ts twoslash
import amagi, { createClient, tools, type ClientOptions, type AmagiClient } from '@ikenxuan/amagi'

const options: ClientOptions = { douyin: { web: { cookie: '' }, app: { signerBaseUrl: '' } } }
const a: AmagiClient = amagi(options)
const b = new amagi(options)
const c = createClient(options)
const bv = tools.bilibili.avToBv(170001)
```

### 构造选项

<auto-type-table path="../../../../../../core/src/client/options.ts" name="ClientOptions" />

配置按平台和端归类。全局 `request` → 平台 `request` → 抖音端 `request` → 方法第二参依次合并，内层优先。`douyin.web.cookie` 仅供 Web；App 使用 `douyin.app.signerBaseUrl` 指向的服务维护身份和签名。

### 实例形状

顶层为 `startServer`、`events`、`on`、`once` 与四个平台：

| 命名空间 | 内容 |
| --- | --- |
| `client.douyin` | `web`、`app` |
| `client.douyin.web` | Web 业务方法、`request`、`auth` |
| `client.douyin.app` | App 业务方法、`request` |
| `client.bilibili` | 业务方法、`request`、`auth`，续期在 `auth.refresh` |
| `client.kuaishou` / `client.xiaohongshu` | 业务方法、`request`、`auth` |

方法名来自 `client/api-names.ts`；`createApi` 只引用原 registry 派生方法，数据接口继续共用 runtime、签名、judge、翻页和事件。`DataApi` 与 `AuthApi` 从注册表和名称映射派生参数与响应类型；具名接口使 IDE 不展开整张端点表。

`debug` 同时控制 `error.raw` 和 `meta.trace`，默认关闭。实例事件总线与历史静态 `amagi.events` 全局总线是两个对象。

## 工具集中在 tools

`import { tools } from '@ikenxuan/amagi'` 无需创建实例。

| 工具组 | 内容 |
| --- | --- |
| `tools.douyin` | `sign`、`apiUrls`、`normalizeCookie`、`credentials`、底层 `passport` |
| `tools.bilibili` | `avToBv`、`bvToAv`、`decodeDanmaku`、`sign`、`apiUrls` |
| `tools.kuaishou` / `tools.xiaohongshu` | `sign`、`apiUrls` |
| `tools.signing` | 签名解析与验证 |
| `tools.signSteps` | 各平台的签名步骤工厂 |

工具不绑定客户端 Cookie 或网络配置，需要身份的低层工具显式传参。`tools.<平台>.apiUrls` 是 v7 请求构造器；旧具名 `douyinApiUrls` 等导出保留 v6 构造器含义。

## 六个导出子路径

日常使用统一包根导入，Express 与 Axios 也可用 `import { express, axios } from '@ikenxuan/amagi'`。现有子路径继续保留，没有增加新子路径。

| 子路径 | 用途 |
| --- | --- |
| `.` | 新客户端、`tools`、公开类型、路由工厂与兼容导出 |
| `./express` / `./axios` | 历史库转发入口 |
| `./signing` | 签名验证的独立浏览器入口；文档站客户端组件使用它以避开 Node 依赖 |
| `./sign-steps` | 历史步骤工厂入口，新 SDK 代码使用 `tools.signSteps` |
| `./compat` | 旧配置、方法名和 v6 信封语义 |

签名验证器所用的浏览器子路径仅依赖环境无关构件；包根面向 Node.js。没有公开 `./client` 或 `./server` 子路径，仓内测试的内部 import 不属于装包契约。

## 旧工厂与静态 Fetcher

`createAmagiClient` 已标记 `@deprecated`，保留旧 `cookies` / `douyinApp` 配置和 `.fetcher` / `.login` 层级，返回 v7 信封。它与新门面共用内部装配与执行管线，具有不同的公开形状。

静态 `<平台>Fetcher`、`createBound<平台>Fetcher` 与构造函数上的历史静态工具属性继续保留原名。新业务代码使用新门面和 `tools`。

## `/compat`

默认导入 `/compat` 保留 v6 参数、`.fetcher`、`.login` 和 `<平台>ApiUrls`。业务结果经薄包装回填顶层 `code` 与旧错误字段，参数校验失败恢复抛出 `ValidationError`，HTTP 路由继续返回 v7 信封。兼容层在 v7 全程保留，计划于 v8 移除。

兼容入口的具名 `createClient`、`amagi`、`CreateApp` 仍指向新门面，只有默认导入和被显式覆盖的旧工厂与 Fetcher 提供兼容语义。

## HTTP 服务

### 门面版（`client.startServer`）

`client.startServer(port = 4567, options = {})` 返回 Express 应用，公开选项为 `openapi` 和测试注入用的 `listen`，监听 `'::'`。平台和端配置传入对应路由；App 保留 `/api/douyin/app_*` 路径。

SDK 方法名重构不改变已发布的 HTTP 路径。所有业务与校验失败仍返回 HTTP 200 的错误信封，未注册路径为 404。`/openapi.json` 在开启 `openapi` 时挂载。

### 全选项版（未导出）

内部 `server/auth.ts` 的 `startServer` 可配置 `host`、`token` 和 `routers`，没有从包根导出。下游需要限制监听地址或添加认证时，使用公开路由工厂和包根 `express` 自行组装，见[HTTP 服务](/docs/v7/usage/advanced/http-server)。

### 路由响应 = 信封 + 一个键

HTTP 响应在 `AmagiResult` 上附加 `requestPath`。生成的 OpenAPI 与 SDK 参考都读取同一组端点声明，SDK 调用路径另由 `API_NAMES` 派生。

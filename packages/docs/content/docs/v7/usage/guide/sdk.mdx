# SDK 使用指南

调用 amagi 有三种写法，区别只在于如何传入 Cookie。日常使用第一种即可，另两种用于特定场景。

## 创建实例（推荐）

将 Cookie 传入 `amagi()`，得到客户端实例，之后即可直接调用各平台的方法，无需再关心 Cookie：

```ts
import amagi from '@ikenxuan/amagi'

const client = amagi({
  cookies: {
    bilibili: 'your_bilibili_cookie',
    douyin: 'your_douyin_cookie',
    kuaishou: 'your_kuaishou_cookie',
    xiaohongshu: 'your_xiaohongshu_cookie'
  }
})

// 通过 client.<平台>.fetcher 调用方法
const video = await client.bilibili.fetcher.fetchVideoInfo({ bvid: 'BV1xx411c7mD' })
const work = await client.douyin.fetcher.fetchVideoWork({ aweme_id: '123456789' })
```

## 不创建实例，每次传入 Cookie

如果只需调用少数几个接口，不想为此创建客户端，可以使用静态 fetcher。方法名与用法相同，只是 Cookie 改为第二个参数，且每次都要传入：

```ts
import amagi from '@ikenxuan/amagi'

const result = await amagi.bilibiliFetcher.fetchVideoInfo({ bvid: 'BV1xx411c7mD' }, 'SESSDATA=xxx; bili_jct=yyy')
```

## 绑定 Cookie 后重复调用

如果既想要静态 fetcher 无需创建实例的简便，又不想每次重复传入 Cookie，可以用 `createBound*Fetcher` 预先绑定 Cookie，之后调用只需传入业务参数：

```ts
import amagi from '@ikenxuan/amagi'

// 预先将 Cookie 绑定到 fetcher
const bilibiliFetcher = amagi.createBoundBilibiliFetcher('your_cookie')
const douyinFetcher = amagi.createBoundDouyinFetcher('your_cookie')

// 后续调用无需再传入 Cookie
const video = await bilibiliFetcher.fetchVideoInfo({ bvid: 'BV1xx411c7mD' })
```

## 返回值：统一封装在「信封」中

无论调用哪个方法，返回的都不是数据本身，而是一层统一的外层结构，称为「信封」（`AmagiResult<T>`）。信封中要么是数据，要么是错误。先判断 `success` 字段：为 `true` 时读取 `data`，为 `false` 时读取 `error`。顶层没有 `code`，请求失败时也不会抛出异常，失败同样以返回值的形式给出。

<Callout type="warn">
  v7 的信封与 v6 的 `Result<T>` 不同：**顶层 `code` 已删除**，`error` 也不再是 `any`。
  v6 用同一个 `code` 混装 HTTP 状态码、平台业务码与内部码，v7 把它们各归各位 ——
  HTTP 状态在 `error.http.status`、平台原始码在 `error.platform.code`、amagi
  自己的错误码在 `error.code`。要整体切回 v6 语义（含顶层 `code`）用
  `@ikenxuan/amagi/compat`，一行改导入即可。
</Callout>

### 使用示例

```ts
import amagi from '@ikenxuan/amagi'
const client = amagi({ cookies: { bilibili: '', douyin: '', kuaishou: '', xiaohongshu: '' } })
const result = await client.bilibili.fetcher.fetchVideoInfo({ bvid: 'BV1xx411c7mD' })

if (result.success) {
  console.log(result.data)
} else {
  console.error(result.message, result.error)
}
```

## 自定义请求头、超时与代理

创建实例时写在 `request` 中，该客户端此后发出的每一条请求都会带上这些配置：

```ts
import amagi from '@ikenxuan/amagi'

const client = amagi({
  cookies: {
    bilibili: 'your_cookie',
    douyin: 'your_cookie',
    kuaishou: 'your_cookie',
    xiaohongshu: 'your_cookie'
  },
  request: {
    headers: {
      'User-Agent': 'Mozilla/5.0 ...'
    },
    timeout: 10000,
    proxy: {
      host: '127.0.0.1',
      port: 7890
    }
  }
})
```

## 平台模块结构

每个平台模块包含以下内容（`request` 与 `apiUrls` 是 v7 新增的两个键：前者用于请求任意接口，见[自定义请求](/docs/v7/usage/advanced/custom-request)；后者是 v7 那份 URL 构造器。v6 那份（`douyinApiUrls` 等带平台名的四个）**不在平台模块上** —— 它从包顶层与 `@ikenxuan/amagi/compat` 到达）：

```ts tab="B站" tab-group="platform"
import amagi from '@ikenxuan/amagi'
const client = amagi({ cookies: { bilibili: '', douyin: '', kuaishou: '', xiaohongshu: '' } })
// fetcher - 数据获取器
client.bilibili.fetcher.fetchVideoInfo({ bvid: 'BV1xx' })
client.bilibili.fetcher.fetchComments({ oid: '123', type: 1 })
client.bilibili.fetcher.fetchUserCard({ host_mid: 123456 })

// sign - 签名算法
client.bilibili.sign.av2bv(170001)
client.bilibili.sign.bv2av('BV1xx411c7mD')

// danmaku - 弹幕解析
// client.bilibili.danmaku.parseDmSegMobileReply(buffer)
```

```ts tab="抖音"
import amagi from '@ikenxuan/amagi'
const client = amagi({ cookies: { bilibili: '', douyin: '', kuaishou: '', xiaohongshu: '' } })
// fetcher - 数据获取器
client.douyin.fetcher.fetchVideoWork({ aweme_id: '123' })
client.douyin.fetcher.parseWork({ aweme_id: '123' })
client.douyin.fetcher.fetchWorkComments({ aweme_id: '123' })

// sign - 签名算法
client.douyin.sign.Mstoken(128)
// client.douyin.sign.AB(url, ua)
// client.douyin.sign.XB(url, ua)
```

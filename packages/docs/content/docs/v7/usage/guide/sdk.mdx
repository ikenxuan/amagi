# SDK 使用指南

所有常规能力从 `@ikenxuan/amagi` 导入。抖音使用 `client.douyin.web` 与 `client.douyin.app` 选择端，其他平台直接调用业务方法。方法名描述业务，不再带 `fetch`、`app` 或 `web` 前缀。

## 创建实例（推荐）

```ts twoslash
import amagi, { tools, type ClientOptions } from '@ikenxuan/amagi'

const options: ClientOptions = {
  request: { timeout: 15000 },
  douyin: {
    web: { cookie: 'your_douyin_web_cookie' },
    app: { signerBaseUrl: 'http://127.0.0.1:8787' }
  },
  bilibili: { cookie: 'your_bilibili_cookie' },
  kuaishou: { cookie: 'your_kuaishou_cookie' },
  xiaohongshu: { cookie: 'your_xiaohongshu_cookie' }
}
const client = amagi(options)

const web = await client.douyin.web.comments({ aweme_id: '7700469970560611833', number: 20 })
const app = await client.douyin.app.comments({ aweme_id: '7700469970560611833', number: 20 })
const video = await client.bilibili.videoInfo({ bvid: 'BV17x411w7KC' })
const work = await client.kuaishou.work({ photoId: '3xq123' })
const note = await client.xiaohongshu.note({ note_id: 'note-id', xsec_token: 'token' })
const bv = tools.bilibili.avToBv(170001)
```

`amagi(options)`、`new amagi(options)` 与具名工厂 `createClient(options)` 返回相同的 `AmagiClient`。配置全部可选；不需要登录的接口可以先用 `amagi()` 尝试。

## 初始化配置

<auto-type-table path="../../../../../../core/src/client/options.ts" name="ClientOptions" />

| 配置 | 用途 |
| --- | --- |
| `request` | 所有平台的网络配置 |
| `douyin.request` | 抖音两端共用的网络配置 |
| `douyin.web.cookie` / `douyin.web.request` | 抖音 Web 身份与网络配置 |
| `douyin.app.signerBaseUrl` / `douyin.app.request` | App 签名服务站点地址与网络配置 |

douyin.app.signerBaseUrl 填签名服务的站点地址（origin），例如 http://192.168.1.76:8787，不要附加 API 路径。amagi 会自动请求该站点下的 /v1/app/sign 和 /v1/app/tt-encrypt。Web 控制台与录样本 CLI 可用环境变量 AMAGI_DOUYIN_APP_SIGNER_BASE_URL 配置同一个站点地址。
| `bilibili` / `kuaishou` | 各自的 `cookie` 与 `request` |
| `xiaohongshu` | `cookie`、`request` 与配对的 `session` |
| `debug` | 失败信封带 `error.raw`，信封带 `meta.trace` |

网络配置依次按 **全局 → 平台 → 端 → 单次调用** 合并，内层优先，`headers` 按字段合并。B站、快手、小红书目前没有端层。

```ts twoslash
import amagi from '@ikenxuan/amagi'

const client = amagi({
  request: { timeout: 10000 },
  douyin: {
    request: { timeout: 15000 },
    web: { cookie: 'ttwid=...', request: { timeout: 20000 } },
    app: { signerBaseUrl: 'http://127.0.0.1:8787', request: { timeout: 30000 } }
  },
  xiaohongshu: {
    session: { cookie: 'a1=...', webSsk: 'paired-ssk', b1: 'paired-b1' }
  }
})
// 只有这次调用使用 25000ms。
const result = await client.douyin.web.work({ aweme_id: '7700469970560611833' }, { timeout: 25000 })
```

小红书的 `session.cookie` 与 `webSsk`、`b1` 等材料应来自同一会话。仅有 Cookie 时可使用 `xiaohongshu.cookie`。

## 抖音 App 接口

需要签名的 App 接口使用的签名服务站点地址配置在 `douyin.app.signerBaseUrl`，填写如 `http://192.168.1.76:8787` 的站点地址，默认空字符串。未配置时方法正常 resolve，返回 `success: false`、`error.code: 'APP_SIGNER_NOT_CONFIGURED'`，不发业务请求；HTTP 入口同样返回 HTTP 200 的错误信封。

```ts twoslash
import amagi from '@ikenxuan/amagi'

const client = amagi({ douyin: { app: {
  signerBaseUrl: 'http://127.0.0.1:8787'
} } })
const result = await client.douyin.app.comments({ aweme_id: '7700469970560611833', number: 20 })
if (result.success) console.log(result.data.comments)
else console.error(result.error.code, result.message)
```

App 设备与 Cookie 现在由 amagi 管理。首次调用时，amagi 生成并持久化设备配置，经签名服务取得 TTEncrypt 密文，再自行请求抖音注册设备、换取 ID，执行激活、游客 Cookie 回调和初始 Feed，保留实际下发的全部 `Set-Cookie`。后续逐页将同一份设备身份、最终 URL、请求头与请求体送到签名服务；服务只执行原生签名或加密，不访问抖音。需要支持客户身份协议的新版签名服务。

`sessionFile` 可选：省略时，设备与 CookieJar 默认保存到实际加载的 `@ikenxuan/amagi` 包内，与该包 `package.json` 同级的 `data/douyin-app-session.json`，重启后直接恢复。工作区源码运行对应 `packages/core/data/`；npm、pnpm 和 Yarn 安装时从模块真实位置查找包名，不依赖消费项目的工作目录，也不拼接固定的 `node_modules` 路径。Yarn PnP 使用包声明的 `preferUnplugged` 解压到磁盘以便保存数据。

显式设置 `douyin.app.sessionFile` 可以覆盖默认路径，相对路径按创建客户端时的工作目录解析。Web 调试工具与采样 CLI 使用同一默认文件，也支持 `AMAGI_DOUYIN_APP_SESSION_FILE`。Cookie 按域、路径、Secure 和有效期发送，业务响应持续更新并保存 Cookie；12 小时后按需刷新，保留设备 ID。`client.douyin.app.guest.snapshot()` 导出当前快照，`await client.douyin.app.guest.refresh()` 主动更新 Cookie。包目录升级或被包管理器重建时，包内数据可能随之删除；需要跨版本保留时可指定包外固定路径。会话文件不包含在发布包中，不应纳入 Git。

amagi 调用签名服务的接口只有两类：`POST /v1/app/tt-encrypt` 传入 gzip 字节的 Base64，返回注册正文密文；`POST /v1/app/sign` 传入设备身份、最终 URL、方法、请求头与正文，返回签名对象。随后由 amagi 请求设备注册、ttwid 回调、激活、Feed 和目标业务接口，签名服务不请求抖音，也不维护 Cookie。

App 不继承 Web Cookie、浏览器头或附加 query；代理、超时与 adapter 等网络配置仍生效。`session: false` 仅供旧的服务端身份协议过渡使用，无法启用新的 amagi 会话管理。

2026 年 11 月 20 日按新流程实际取得 `store-region`、`store-region-src`、`install_id`、`ttreq`、`ttwid`、`odin_tt`；Feed 和公开合集成功。带上这些由同一设备取得的 Cookie 后，三种搜索仍返回验证或风控，因此不会把“已补齐 Cookie”表述成“搜索已解除风控”。Cookie 完整性指保留实际响应，不是伪造一组固定 Cookie 键。

接口参数与实测限制见[抖音 SDK 方法参考](/docs/v7/usage/api/sdk/douyin)。喜欢列表、完整搜索、直播详情、主页推荐和动态表情仍有实验性限制；未登录、风控或空响应按错误信封处理。App 弹幕只返回指定起点的片段，`total` 不等于已获取条数。

2026 年 11 月 20 日使用 Android 40.7.0 游客签名逐项复测，业务参数复用 Web 请求集合，实际响应来自 App 上游：

| `client.douyin.app` 方法 | 实测结果 |
| --- | --- |
| `slidesWork` | 成功。覆盖图文与视频混合、纯短片两种合辑，保存 2 份 App 样本并生成 `DouyinAppSlidesWorkResponse`。 |
| `textWork` | 成功。取得 `aweme_type=163` 的文字作品详情，保存 App 样本并生成 `DouyinAppTextWorkResponse`。 |
| `userLikes` | HTTP 200、响应体为空；验证头指示 `subtype=text`，返回 `CAPTCHA_REQUIRED`。 |
| `userRecommendations` | HTTP 200、`status_code=8`、`status_msg=用户未登录`，返回 `LOGIN_REQUIRED`。 |
| `mixWorks` | 成功。APK 对照确认原实现把翻页方向传反：`pull_type=1` 在 `cursor=0` 时返回空壳，改为向后取的 `pull_type=2` 并补齐 `skip_local_cache=false`、`req_from=app` 后正常。用户样本合集取得 13 条；保存真实 App 样本并生成 `DouyinAppMixAwemeResponse`。 |
| `search` | 当前签名设备上三种搜索仍返回 `verify_check` 滑块。已发现并修复签名端漏传实际请求头和 POST 摘要的问题，也补齐 APK 搜索场景参数；本地原生库对照仍未拿到成功数据。该结果不能推导为官方 App 的游客搜索不可用。 |

### 表情资源与 APK 版本

`client.douyin.app.emojiResource({ version_name? })` 不需要签名服务。`version_name` 可选，默认 `40.7.0`；它决定服务端下发哪个 APK 版本可用的资源包，旧版资源可能不完整。`device_platform=android` 由内部补齐。

```ts twoslash
import amagi from '@ikenxuan/amagi'
const client = amagi()
// ---cut---
const current = await client.douyin.app.emojiResource()
const older = await client.douyin.app.emojiResource({ version_name: '17.4.0' })
const guest = await client.douyin.app.guestEmojiResource({ version_name: '17.4.0' })
```

`guestEmojiResource()` 保留历史域名与默认版本 `17.4.0`，同样支持传入版本。两条入口都返回资源地址和 MD5；应在相同版本下比较资源，日志字段与下载地址的临时签名会变化。

## 返回值：统一封装在「信封」中

业务接口返回 `AmagiResult<T>`。以 `success` 判别，成功读 `data`，失败读 `error`。顶层没有 `code`；请求失败返回错误信封。

```ts twoslash
import amagi from '@ikenxuan/amagi'
const client = amagi()
// ---cut---
const result = await client.bilibili.videoInfo({ bvid: 'BV17x411w7KC' })
if (result.success) {
  console.log(result.data)
} else {
  console.error(result.error.kind, result.error.code, result.message)
}
```

## 平台模块结构

| 入口 | 数据接口 | 会话和身份 | 自定义请求 |
| --- | --- | --- | --- |
| `client.douyin.web` | `work`、`comments`、`userProfile` 等 | `.auth` | `.request` |
| `client.douyin.app` | `work`、`comments`、`userProfile` 等 | 签名服务维护游客身份 | `.request` |
| `client.bilibili` | `videoInfo`、`comments`、`userProfile` 等 | `.auth` | `.request` |
| `client.kuaishou` | `work`、`comments`、`userProfile` 等 | `.auth` | `.request` |
| `client.xiaohongshu` | `note`、`comments`、`userProfile` 等 | `.auth` | `.request` |

签名、URL 构造、AV/BV 转换与解码放在包根 `tools`，详见[工具集](/docs/v7/usage/guide/utilities)。尚未收录的接口通过[自定义请求](/docs/v7/usage/advanced/custom-request)处理。HTTP 路径仍按原注册表派生；SDK 方法重命名不改变 HTTP 路径。

## 扫码登录

登录会话放在 `auth`。`qrcode()` 创建会话，`resume(blob)` 恢复会话。抖音使用 `client.douyin.web.auth`，其他平台使用 `client.<平台>.auth`。

```ts twoslash
import amagi from '@ikenxuan/amagi'
const client = amagi()
// ---cut---
const outcome = await client.bilibili.auth.qrcode().watch({
  onQrcode: (qr) => console.log(qr.content),
  onScanned: () => console.log('已扫码')
})
if (outcome.ok) console.log(outcome.credential.cookie)
```

会话返回 `{ ok, credential } | { ok, error }`，与业务信封不同。也可通过异步迭代或 `start()` + `next()` 消费。登录成功的 Cookie 由调用方保存，并用于下一次创建客户端。状态机与平台差异见[翻页与会话](/docs/v7/dev/internals/session)。

`client.douyin.web.auth.status()` 检查配置的 Web Cookie；B站使用 `client.bilibili.auth.status({})`。这些检查不会自动切换客户端身份。

## B站 Cookie 续期

```ts twoslash
import amagi from '@ikenxuan/amagi'
const client = amagi()
declare const cookie: string
declare const refreshToken: string
// ---cut---
const refreshed = await client.bilibili.auth.refresh({ cookie, refreshToken })
if (refreshed.ok) {
  console.log(refreshed.credential.cookie)
  console.log(refreshed.credential.refreshToken)
} else {
  console.error(refreshed.error.code, refreshed.error.message)
}
```

`cookie` 至少包含 `SESSDATA` 和 `bili_jct`，`refreshToken` 来自登录响应。成功后将新 Cookie 和 refreshToken 一起持久化。

## 迁移旧调用

主客户端不再提供 `.fetcher`、`.login` 或实例工具集。`createAmagiClient` 保留旧配置和调用层级，仍返回 v7 信封；静态 Fetcher 与绑定工厂保留原方法名。需要旧 v6 信封和校验异常语义时使用 `/compat`。迁移对照见[迁移指南](/docs/v7/usage/migration-v7)。
